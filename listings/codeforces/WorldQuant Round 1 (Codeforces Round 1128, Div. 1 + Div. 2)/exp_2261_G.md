# 2261G — 1 2 3 and XOR, Where Did Everybody Go?

[Problem](https://codeforces.com/contest/2261/problem/G) · [C++17 code](comp_2261_G.cpp)

## Problem

For a nonempty subarray, choose one element and increase it by any nonnegative amount, including zero. Let `f` be the smallest achievable XOR of that subarray. Sum `f` over all subarrays. Values have at most 25 bits, and total `n` is at most 400,000.

## First solve one subarray

Let `X` be its XOR and `M` its AND. If `X & ~M` is zero, `f=X`. Otherwise let `p` be the highest set bit of `X & ~M`. Then:

```text
f = (X >> (p+1)) << (p+1)
```

At bit `p`, the XOR is one and some element has zero. Flip that element's bit `p` to one and choose its lower bits to cancel the remaining XOR. This increases the selected element regardless of the lower bits. All higher XOR bits are unchanged.

No better result can change a higher bit. A zero higher XOR bit cannot become one in a smaller answer. At a higher set XOR bit, every element has one; changing an element's first differing bit from one to zero would decrease it, which is forbidden.

## Count the answer one bit at a time

Bit `b` contributes exactly when:

```text
(M has bit b set) and (X >> b) == (M >> b)
```

Why equality is sufficient and necessary: `M_b=1` means every element has that bit. A contributing `X_b=1` therefore requires odd subarray length. For odd length, each higher AND-one bit also has XOR one. Equality of the shifted values consequently says precisely that no higher XOR-one/AND-zero bit can erase bit `b`.

Use zero-based suffix XORs `T[i]=a[i]^...^a[n-1]` and `T[n]=0`. For subarray `[i,r]`, `X=T[i]^T[r+1]`. With fixed AND `M`, count endpoints satisfying:

```text
T[r+1] >> b == (T[i] ^ M) >> b
```

## Group endpoints by AND changes

For each start `i`, precompute the first position at or after `i` whose bit `j` is zero. Sort the 25 bit indices by these positions. As the right endpoint moves, an AND bit disappears only at its first zero; there are at most 25 changes.

For a fixed answer bit `b`, starts with `a[i]_b=0` can be skipped. Process the endpoint ranges `[L,R)` where `M>>b` stays fixed, and stop when bit `b` disappears. Changes below `b` are irrelevant.

## Offline frequency queries

For one endpoint range, the required shifted suffix value is a fixed `key`. Count matching endpoints in `[L,R)` as:

```text
count(end >= L, key) - count(end >= R, key)
```

Create a positive event at `L` and a negative event at `R`. Sweep positions from right to left, inserting `T[position+1]>>b` before answering events at that position. A direct frequency table answers every event in constant time. Multiply the resulting count by `1LL<<b`.

The events count each contributing bit of each subarray exactly once, establishing correctness.

## Complexity

- Time: `O(n*25^2)`; sorting the 25 next-zero positions is also within this bound.
- Space: `O(n*25 + 2^25)`.
- Peak allocated data at maximum `n` is approximately 330–350 MiB, within G's 1 GiB limit.
- The answer requires `long long`; a bound of `n(n+1)/2 * (2^25-1)` still fits signed 64-bit.

## Execution tips and common mistakes

- Use a direct integer frequency array instead of hash-map lookup for millions of events. This is why the larger memory limit is useful.
- Store events in flat arrays with linked indices; avoid one heap allocation per event.
- Reserve event capacity once and reuse it between bit sweeps.
- Clear only frequency entries touched by the sweep. Clearing all `2^25` entries for every bit wastes work.
- Skip answer bits absent from the OR of the input.
- Process equal next-zero positions together; otherwise zero-length ranges and repeated updates are easy to mishandle.
- Insert the endpoint suffix before processing that position's events.
- `~key` encodes a subtract event, including when `key=0`; `-key` would lose the sign for zero.
- Increasing by zero is legal. Singleton subarrays therefore contribute their original element.
- Do not replace increasing an element with XORing it arbitrarily; the highest changed bit must move from zero to one.

## Verification

The algorithm matched direct increment enumeration on all 1,364 arrays of lengths 1 through 5 over values 0 through 3. It also matched a quadratic XOR/AND oracle on 10,000 random arrays up to 25 bits and passed all four official samples.
