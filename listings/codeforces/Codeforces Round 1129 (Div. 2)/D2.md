**D2. Number Operating — Hard Version — Complete C++20 Solution**

[Original problem](https://codeforces.com/contest/2277/problem/D2) · [C++ source](D2.cpp)

**Problem in brief**

The operations and function `f(n)` are the same as in the easy version: consecutive additions add `1,2,4,...`, while a subtraction decreases the value by one and resets the consecutive-addition count.

For each interval `[l,r]`, output the sum of minimum operation counts modulo `998244353`. Now an interval may contain as many as `10^18+1` values, and there may be `10000` queries. This document includes the single-target derivation so it can be read independently of D1.

**Single-target recurrence and its proof**

First solve one target `n`. A consecutive run of `j` additions increases the value by `2^j-1`. Combining a run with the subtraction that separates it from another run gives a useful unit:

- net increase `2^j-2`;
- operation count `j+1`.

For `n >= 4`, write `P = 2^k`, where `P <= n < 2P`. The recurrence used in the program is

`f(n) = min(f(n-P+2) + k+1, 2P-n+k)`.

The first choice uses a length-`k` run and a separating subtraction, then solves the remaining increase. The second uses `k+1` additions to reach `2P-1`, then subtracts down to `n`. The starting values are `f(0)=0, f(1)=1, f(2)=3, f(3)=2`.

For example, `f(4)=6`: three additions reach `7`, and three subtractions reach `4`.

An exchange argument explains why these two choices cover an optimum. For a sequence containing `b` addition runs, let their lengths be `j_1,...,j_b`. There must be at least `b-1` subtractions. Write the number of extra subtractions as `q`. Then

`n = 1 + sum(2^j-2) - q`.

If we add `n` to the operation count, the result is

`sum(2^j + j - 1)`.

Thus minimizing operations is equivalent to selecting run lengths with total capacity `sum(2^j-2) >= n-1`, minimizing the total price `sum(2^j+j-1)`. Surplus capacity is removed by the extra subtractions. Any such selection can be realized by putting one subtraction between runs and the extra subtractions at the end.

For `n >= 2`, length-one runs have zero capacity and can be discarded. Two runs of the same length `j >= 2` can be replaced by one run of length `j+1`: capacity increases by two, while price changes by `2-j <= 0`. Repeating this replacement leaves an optimum with distinct run lengths.

All lengths below `k` together provide capacity only `2^k-2k`, which is less than `n-1`. Hence an optimum needs a run of length at least `k`. A length above `k+1` costs more than a single length-`k+1` run that already covers the target. Therefore an optimum's longest run is `k` or `k+1`.

In the latter case, that run alone is sufficient. In the former, remove one length-`k` run and solve the residual covering problem, giving the first recurrence term. This proves the recurrence.

**Extending to arbitrary intervals**

Enumerating the interval is now impossible. Define `G(N) = sum(f(x), x=0..N)`. The answer is `G(r)-G(l-1)`.

Within a block `[P,2P-1]`, D1 compares a recursively shifted function with a descending straight line. We can identify exactly where they cross. Set `m=n-P+2`. The recursive choice wins precisely when

`f(m)+m <= P+1`.

The left side is nondecreasing: an optimal way to reach `m+1`, followed by a subtraction, proves `f(m) <= f(m+1)+1`. Therefore binary search finds the last valid `m`, called `position[k]`. Since `f(m) >= 2` for `m >= 2`, this position is at most `P-1`.

Let `cutoff[k] = P + position[k] - 2`. On `[P,cutoff[k]]`, use the recursive expression; after that, use the straight line. These intervals include ties in the first part.

To evaluate `G(N)`, let `b=min(N,cutoff[k])` and `c=b-P+1`. Then

`G(N) = G(P-1) + G(b-P+2) - G(1) + c(k+1) + tail`.

The tail covers `b+1,...,N`. Its values decrease by one, so

`tail = (N-b) * ((2P+k-b-1) + (2P+k-N)) / 2`.

Division by two is implemented with the modular inverse of two. Each formula makes only one recursive call to a smaller highest-bit block. Precompute `G(P-1)` in increasing order of `k`; all dependencies then already exist. Small prefixes are `G(0)=0, G(1)=1, G(2)=4, G(3)=6`, and negative prefixes return zero.

Precomputation takes **O(log^3 V)**: O(log V) blocks, each with a binary search whose predicate evaluates D1. Every query takes **O(log V)** time, with **O(log V)** total auxiliary space. All arithmetic fits signed 64-bit integers because products of large counts are reduced modulo the modulus before multiplication.

**Worked examples**

These are custom examples.

The first three intervals have answers `0`, `6`, and `18`, using the values listed below:

| `n` | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| `f(n)` | 0 | 1 | 3 | 2 | 6 | 5 | 4 | 3 |

For the block `[8,15]`, take `P=8` and `k=3`. We binary-search the condition `m+f(m) <= 9`:

- `m=2`: `2+3=5`, valid.
- `m=3`: `3+2=5`, valid.
- `m=4`: `4+6=10`, invalid.

Because the predicate is monotone, the last valid position is `3`. Hence `cutoff=8+3-2=9`. The recursive formula applies at `8,9`; the remaining values form a descending arithmetic progression.

| Target | 8 | 9 | 10 | 11 | 12 | 13 | 14 | 15 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Minimum operations | 7 | 6 | 9 | 8 | 7 | 6 | 5 | 4 |
| Selected expression | Recursive | Recursive | Straight line | Straight line | Straight line | Straight line | Straight line | Straight line |

Their sum is `52`. To compute `G(15)` with the prefix formula:

```text
G(7) = 24
b = 9
c = 2
shifted recursive sum = G(3)-G(1) = 6-1 = 5
constant part = c*(k+1) = 2*4 = 8
tail = (9+8+7+6+5+4) = 39
G(15) = 24+5+8+39 = 76
```

Therefore the last query, `[0,15]`, returns `76`. The `[8,15]` query returns `G(15)-G(7)=76-24=52`.

**Implementation notes**

The arrays have 60 entries, sufficient for every highest bit of an endpoint up to `10^18`. Precomputation processes bit indices `2..59` in increasing order. When evaluating `before[k]=G(2^k-1)`, only smaller, initialized blocks are accessed.

The first part of each block is nonempty: `m=2` always satisfies `m+f(m)=5 <= P+1` for `P>=4`. Its last shifted argument is at most `P-1`, so the recursion strictly moves to a lower highest bit. The arithmetic-progression term may have length zero, which the same formula handles. Reduction after each modular product avoids overflow. The inverse `(MOD+1)/2` performs modular division by two.

**Complete C++20 code**

```cpp
#include <algorithm>
#include <array>
#include <bit>
#include <iostream>
using namespace std;
using int64 = long long;
constexpr int64 MOD = 998244353;
constexpr int64 INV2 = (MOD + 1) / 2;

int highest_bit(int64 n) {
    return static_cast<int>(bit_width(static_cast<unsigned long long>(n))) - 1;
}

int64 minimum_operations(int64 n) {
    static constexpr int base[] = {0, 1, 3, 2};
    if (n < 4) return base[n];
    int k = highest_bit(n);
    int64 power = 1LL << k;
    return min(minimum_operations(n - power + 2) + k + 1,
               2 * power - n + k);
}

struct PrefixSolver {
    array<int64, 60> cutoff{}, before{};

    int64 prefix(int64 n) const {
        if (n < 0) return 0;
        static constexpr int small[] = {0, 1, 4, 6};
        if (n < 4) return small[n];
        int k = highest_bit(n);
        int64 power = 1LL << k;
        int64 end = min(n, cutoff[k]);
        int64 count = end - power + 1;
        int64 result = (before[k] + prefix(end - power + 2) - 1 + MOD
                      + (count % MOD) * (k + 1)) % MOD;
        // Beyond cutoff[k], f is an arithmetic progression with difference -1.
        int64 tail = n - end;
        int64 first = 2 * power + k - end - 1;
        int64 last = 2 * power + k - n;
        result = (result + ((first + last) % MOD) * (tail % MOD) % MOD * INV2) % MOD;
        return result;
    }

    PrefixSolver() {
        for (int k = 2; k < 60; ++k) {
            int64 power = 1LL << k;
            // h(m) = m + f(m) is nondecreasing. Find its last valid m.
            int64 low = 2, high = power - 1, position = 2;
            while (low <= high) {
                int64 middle = low + (high - low) / 2;
                if (middle + minimum_operations(middle) <= power + 1) {
                    position = middle;
                    low = middle + 1;
                } else {
                    high = middle - 1;
                }
            }
            cutoff[k] = power + position - 2;
            before[k] = prefix(power - 1);
        }
    }
};

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    PrefixSolver solver;
    int t;
    cin >> t;
    while (t--) {
        int64 l, r;
        cin >> l >> r;
        cout << (solver.prefix(r) - solver.prefix(l - 1) + MOD) % MOD << '\n';
    }
}
```
