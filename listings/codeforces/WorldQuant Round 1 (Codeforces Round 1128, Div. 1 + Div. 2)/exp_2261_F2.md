# 2261F2 — Plegma II: Ask Me Any Cell (Hard Version)

[Problem](https://codeforces.com/contest/2261/problem/F2) · [C++17 code](comp_2261_F2.cpp)

## Problem

Encode every cell of an `n` by `n` grid using binary grids and one shared memoryless decoder. At each step the decoder sees only the number of ones in its current rectangle and deletes one outer row or column. After `2n-2` deletions, exactly the encoded cell must remain.

Input contains one `n`: 3 or any integer from 10 through 40. Output all `n^2` grids in target row-major order, then an action string of length `n^2+1`. Every grid must use at most the optimal worst-case zero count `f(n)`.

The tight value is `f(n)=3` for `n>=3`. The [official tutorial](https://codeforces.com/blog/entry/157917) proves the lower bound by showing that with two zeros some corner is unreachable. The code implements an explicit three-zero upper bound.

## Decoder: the zero count is a mode

A rectangle with `h*w` cells and `z` zeros gives signal `S=h*w-z`. Place zeros so that deleting a selected strip decreases `z` exactly when the route needs to switch direction.

| Stage | Zero count | Action |
|---|---:|---|
| `h` rows, `n` columns, `h>=4` | 3 | `U` |
| Same | 2 | `D` |
| 3 rows, `w>=2` columns | 3 | `R` |
| Same | 2 | `L` |
| Same | 1 | `R` |

Implement these entries with:

```text
A[0]=A[1]=U; A[2]=D
A[3*w-3]=R; A[3*w-2]=L; A[3*w-1]=R   for 2<=w<=n
A[n*h-3]=U; A[n*h-2]=D                for 4<=h<=n
```

The ranges are `0..2`, `3..3n-1`, and at least `4n-3`. Since `4n-3 > 3n-1` for `n>=3`, no action assignment conflicts.

## Encoder: plan the route first

For target `(r,c)`, define `up=min(r-1,n-3)` and `p=r-up`.

Perform `up` top deletions in mode 3 and `n-3-up` bottom deletions in mode 2. Exactly three rows remain, and the target occupies their `p`-th row.

For `p<=2`, delete left columns in mode 2 until the target becomes the left border, then right columns in mode 1. The final column has one zero. For `p=1`, put that zero in the bottom cell: `D` removes it, then another `D` retains the top cell. For `p=2`, put it in the middle cell: `D` keeps the zero, then `U` retains the middle cell.

For `p=3`, delete right columns in mode 3, then left columns in mode 2. Enter the final column with zeros in its top two cells. Two `U` moves remove one zero each and retain the bottom cell.

Empty phases are omitted. This preserves a non-increasing zero-count schedule even at edge targets.

## Realizing the schedule

Start with an all-ones grid. If a step needs `z_before-z_after` zeros to disappear, place that many in the strip it deletes. These strips are disjoint, and the planned drops fit their sizes. Add any surviving zero at the final target.

The total zeros telescope to the initial mode, at most three. Inductively, the zero count before each step matches the schedule, so the decoder follows the intended route and ends at the target.

## Complexity and execution tips

- Time: `O(n^4)`, the unavoidable number of cells printed.
- Space: `O(n^2)`; process one target at a time.
- Reserve the low signal entries for the final-column phase.
- Keep the row stage at full width and the column stage at height three; those dimensions make the mode values unambiguous.
- Every target requires exactly `2n-2` legal moves. Check border targets and empty phases.
- Print only grids and the action table, with no test-case count or phase labels.
- Fast buffered output matters more than micro-optimizing the three zero placements.

## Verification

All 21,864 target cells for every permitted `n` were simulated. Each decision used only the actual remaining rectangle's signal. Every route retained its target, finished at that single cell, and used at most three zeros.
