# 2261D2 — Come Be My Friend, Don't Be So Scared (Hard Version)

[Problem](https://codeforces.com/contest/2261/problem/D2) · [C++17 code](comp_2261_D2.cpp)

## Problem

The detector task from D1 now has existing intervals. Add the minimum number of new intervals so that the combined report vector is different at every position.

## Representing existing reports

Assign each existing detector two random 64-bit values. XOR them into a difference array at `l` and `r+1`. A prefix XOR gives a pair of hashes for the set of detectors active at each position.

Equal active sets always have equal hashes. Different active sets collide with negligibly small probability under the randomized model. The implementation is therefore probabilistic. A `map` compresses the hash pairs into integer labels; its lookup complexity is deterministic logarithmic time.

## Greedy cuts

Scan positions left to right. Remember each label's last position and the most recent cut. If the current label already appeared after that cut, place a new cut immediately before the current position. Every resulting region contains each label at most once.

The intervals between consecutive occurrences of an equal label are nested or disjoint. Crossing equal-label intervals would force an existing detector to leave and re-enter an interval, contradicting contiguity. The smallest disjoint gaps each require a new detector endpoint. The greedy scan selects one endpoint per such gap, giving a minimum count `q` of internal cuts.

## Turning cuts into detectors

A cut `b` is a boundary between positions `b` and `b+1`.

1. If `q = 0`, existing reports already distinguish every position.
2. If `q` is odd, add boundary `0`.
3. If `q` is even and the first and last regions share any existing label, add boundaries `0` and `n`.

Sort order is already maintained. With `2k` boundaries `c[0] < ... < c[2k-1]`, output:

```text
[c[i] + 1, c[i+k]], for i = 0 .. k-1
```

The first half starts detectors; the second half ends them in the same order. All region reports are distinct except possibly the two exterior regions. The shared-label check handles that exception.

## Optimality and complexity

The `q` mandatory disjoint gaps need at least `q` endpoints. Normally this costs `ceil(q/2)` detectors. If `q` is even and an old label occurs in both exterior regions, using only `q` internal endpoints gives those two occurrences identical new reports. One additional detector is necessary and sufficient.

- Time: `O(m + n log n)`.
- Space: `O(n)`.

## Execution tips and common mistakes

- Use a difference array; touching every cell of every existing interval can be quadratic.
- Use both 64-bit hashes; truncating to 32 bits weakens collision protection substantially.
- Check every label in the first and last regions, not just a single position in each.
- `0` and `n` are boundaries. Conversion back to an inclusive detector interval needs `left + 1`.
- Take the zero-cut early return before accessing `cuts.front()` or `cuts.back()`.
- Adjacent-pair separation alone is insufficient: distant positions may still have identical reports.

## Verification

The construction and minimum count matched exact brute force for 43,866 configurations: every existing-detector subset for `n <= 5`, plus 10,000 random configurations for `n = 6`. Those checks used exact report sets, avoiding randomized collisions in the oracle.
