**D1. Number Operating — Easy Version — Complete C++20 Solution**

[Original problem](https://codeforces.com/contest/2277/problem/D1) · [C++ source](D1.cpp)

**Problem in brief**

Start with `x=0`. An addition increases `x` by `2^k`, where `k` is the number of consecutive additions immediately preceding it. A subtraction decreases `x` by one and resets the next addition to `+1`. Negative values are permitted.

Let `f(n)` be the minimum operation count to reach `n`. Given `l r`, print the sum of `f(n)` for `l <= n <= r`, modulo `998244353`. Endpoints are between zero and `10^18`, but the total number of integers across all requested intervals is at most `200000`.

**Algorithm and correctness**

First solve one target `n`. A consecutive run of `j` additions increases the value by `2^j-1`. Combining a run with the subtraction that separates it from another run gives a useful unit:

- net increase `2^j-2`;
- operation count `j+1`.

For `n >= 4`, write `P = 2^k`, where `P <= n < 2P`. The recurrence used in the program is

`f(n) = min(f(n-P+2) + k+1, 2P-n+k)`.

The first choice uses a length-`k` run and a separating subtraction, then solves the remaining increase. The second uses `k+1` additions to reach `2P-1`, then subtracts down to `n`. The starting values are `f(0)=0, f(1)=1, f(2)=3, f(3)=2`.

For example, `f(4)=6`: three additions reach `7`, and three subtractions reach `4`.

An exchange argument explains why these two choices cover an optimum. For a sequence containing `b` addition runs, let their lengths be `j_1,...,j_b`. There must be at least `b-1` subtractions. Write the number of extra subtractions as `q`. Then

`n = 1 + sum(2^j-2) - q`.

If we add `n` to the operation count, the result is

`sum(2^j + j - 1)`.

Thus minimizing operations is equivalent to selecting run lengths with total capacity `sum(2^j-2) >= n-1`, minimizing the total price `sum(2^j+j-1)`. Surplus capacity is removed by the extra subtractions. Any such selection can be realized by putting one subtraction between runs and the extra subtractions at the end.

For `n >= 2`, length-one runs have zero capacity and can be discarded. Two runs of the same length `j >= 2` can be replaced by one run of length `j+1`: capacity increases by two, while price changes by `2-j <= 0`. Repeating this replacement leaves an optimum with distinct run lengths.

All lengths below `k` together provide capacity only `2^k-2k`, which is less than `n-1`. Hence an optimum needs a run of length at least `k`. A length above `k+1` costs more than a single length-`k+1` run that already covers the target. Therefore an optimum's longest run is `k` or `k+1`.

In the latter case, that run alone is sufficient. In the former, remove one length-`k` run and solve the residual covering problem, giving the first recurrence term. This proves the recurrence.

Evaluate it for every integer in `[l,r]`. The recursive argument becomes at most `P+1` and falls below `P` after at most one more step, so evaluation takes **O(log V)** time. Total time is **O((r-l+1) log V)** per test case, with **O(log V)** stack space.

**Worked examples**

These are custom examples.

| Target `n` | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| `f(n)` | 0 | 1 | 3 | 2 | 6 | 5 | 4 | 3 |

Thus `[0,0]` gives `0`, `[1,3]` gives `1+3+2=6`, and `[4,7]` gives `6+5+4+3=18`.

For target `4`, three additions produce `0 -> 1 -> 3 -> 7`, followed by `7 -> 6 -> 5 -> 4`. This takes six operations. The recurrence gives the same result:

```text
P=4, k=2
recursive choice = f(4-4+2)+3 = f(2)+3 = 6
overshoot choice = 8-4+2 = 6
f(4)=6
```

Target `10` illustrates why both branches matter:

```text
P=8, k=3
recursive choice = f(10-8+2)+4 = f(4)+4 = 10
overshoot choice = 16-10+3 = 9
f(10)=9
```

Indeed, four additions reach `15`, and five subtractions reach `10`. For target `127=2^7-1`, seven consecutive additions suffice and are optimal.

**Implementation notes**

`std::bit_width` finds the highest set bit without floating-point logarithms. Values and powers use `long long`. The largest power needed is `2^59`, and twice that power fits signed 64-bit arithmetic. The four base values prevent the recurrence from recursing into itself on tiny arguments. Only the accumulated interval answer is reduced modulo the modulus; each individual `f(n)` is evaluated exactly.

**Complete C++20 code**

```cpp
#include <algorithm>
#include <bit>
#include <iostream>
using namespace std;
using int64 = long long;
constexpr int64 MOD = 998244353;

int64 minimum_operations(int64 n) {
    static constexpr int base[] = {0, 1, 3, 2};
    if (n < 4) return base[n];
    int k = static_cast<int>(bit_width(static_cast<unsigned long long>(n))) - 1;
    int64 power = 1LL << k;
    return min(minimum_operations(n - power + 2) + k + 1,
               2 * power - n + k);
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int t;
    cin >> t;
    while (t--) {
        int64 l, r, answer = 0;
        cin >> l >> r;
        for (int64 n = l; n <= r; ++n) {
            answer += minimum_operations(n);
            if (answer >= MOD) answer -= MOD;
        }
        cout << answer << '\n';
    }
}
```
