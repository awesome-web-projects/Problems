# 2261H — Oh Tree Tree Tree, No Need to Leave

[Problem](https://codeforces.com/contest/2261/problem/H) · [C++17 code](comp_2261_H.cpp)

## Problem and protocol

This is a two-run communication problem. Isabel encodes a binary message in a complete binary tree. The judge chooses a node, flips its bit, and swaps its child subtrees if it is internal. Tara must recover the original message without knowing that node.

The same executable handles both runs. Input begins with `first` for encoding or `second` for decoding, then a test-case count. Each case has `n h` and a binary string: the message in the first run, or the relabelled tree in the second. Cases may be reordered between runs.

The main setting is `n=2030, h=11`; the example has `n=1, h=2`.

## Preserve bit order with a bit-directed DFS

Encode a sequence by preorder traversal. Store its next bit at the current node. If the bit is zero, visit the left child first; if one, visit the right child first. Always traverse the other child afterwards.

Decode by the identical traversal rule, reading the node bits instead of writing them.

Suppose an internal node's bit changes from `x` to `x^1`. Its children are also swapped, so the child chosen by `x^1` after the swap is the same original child chosen by `x`. Both subtrees are therefore visited in their original order. Only the current node's read bit changes. A flipped leaf also changes exactly one read bit.

Thus the recovered sequence has exactly one bit error and no ordering errors.

## Correct that bit with a Hamming code

Use sequence indices `1..N`, with `N=2^h-1`. Reserve powers of two as parity positions. Put the message in the remaining positions and pad unused data positions with zeros.

Choose parity bits so that the XOR of all indices containing a one is zero. Initially parity bits are zero; compute the XOR `syndrome` of data-one indices, and set parity position `2^j` according to bit `j` of this XOR. This cancels the syndrome.

After decoding the tree, XOR the indices of all recovered ones. If sequence position `p` flipped, the result is exactly `p`, because toggling membership of `p` XORs the syndrome with `p`. Flip that position and read the non-parity positions to recover the message.

For `h=11`, there are `2047-11=2036` data positions, enough for 2030 message bits and six zero padding bits. For `h=2`, this automatically gives the repetition code `000` or `111` for the one-bit message.

## Complexity

- Time: `O(2^h)` per case in either mode.
- Space: `O(2^h)`.
- Recursion depth: `O(h)`, at most 11 here.

## Execution tips and common mistakes

- Use the stored/read bit to choose the first child in both modes. A conventional fixed-order DFS loses synchronization after a subtree swap.
- Hamming indices refer to traversal-sequence positions, not heap labels in the output tree.
- Use one XOR of set-bit indices; there is no need to scan all nodes separately for each parity check.
- Keep sequence positions one-based and reset the traversal counter for each test case.
- Do not use files or retained state to communicate between runs. The message is carried entirely by the tree.
- The judge generates `second` input from your encoder. A literal sample decoder input can belong to a different illustrative encoding; test the two phases together.
- The executable reads the official `first`/`second` protocol, not the jury's separate hack-description format containing the corrupted node.
- Return exactly the first `n` non-parity bits; do not print the padding.

## Verification

The strategy passed 43,120 corruption/decoding tests: every message and every corrupted node for heights 2 through 4, plus every one of the 2,047 possible corrupted nodes for six full-size 2030-bit messages.
