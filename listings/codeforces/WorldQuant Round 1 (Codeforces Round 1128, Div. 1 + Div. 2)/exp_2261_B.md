# 2261B — What's the Capital of France?

[Problem](https://codeforces.com/contest/2261/problem/B) · [C++17 code](comp_2261_B.cpp)

## Problem

An operation selects adjacent ratings and increments the smaller rating by one. Equal ratings stay unchanged. Maximize the bitwise OR of all ratings after any number of operations.

## Solution

Let `lo` and `hi` be the initial minimum and maximum. If they are equal, return that value. Otherwise, let `b` be the highest set bit of `lo ^ hi`. The answer is:

```text
hi | ((1LL << (b + 1)) - 1)
```

The implementation builds the low-bits mask by repeatedly shifting `lo ^ hi`; it handles the all-equal case without a separate logarithm operation.

## Why it works

The maximum cannot increase: an incremented value is strictly below its neighbor beforehand. No value decreases. Consequently, every final rating lies in the original interval `[lo, hi]`.

All values in this interval have the same binary prefix above bit `b`. No operation can change that prefix, so setting every bit from `b` down to zero or one can give at most the stated answer.

This upper bound is reachable. Keep an occurrence of the minimum unchanged. Starting at a maximum, raise successive positions on a path toward that minimum to `hi`. Its neighbor now has value `hi`, so the selected minimum can be increased to any value in `[lo, hi]`.

Choose the value with the common high prefix, bit `b` equal to zero, and all lower bits equal to one. It lies in `[lo, hi]`. Its OR with `hi` sets every bit through `b`, reaching the bound.

For `[4, 6]`, increment 4 to 5: `5 | 6 = 7`. For `[8, 8, 8]`, no operation changes a value, so the answer is 8.

## Complexity

- Time: `O(n + log(hi + 1))`; the bit loop has at most 30 iterations here.
- Extra space: `O(1)`, with streamed input.

## Execution tips and common mistakes

- Keep only the minimum and maximum; the array and its order are unnecessary after the proof.
- Avoid simulating increments: their count can be enormous.
- Use integer bit operations instead of floating-point `log2`.
- Do not call `__builtin_clz(0)` in an alternative implementation.
- `1LL` and `long long` make shifts and masks safe without relying on signed 32-bit behavior.
